# docs/GET_STARTED.md

This guide provides a complete, step-by-step process for first-time M3TAL users to set up their system.

---

## 1. Prerequisites

Docker Engine and Docker Compose V2 must be installed and operational on your system.

Verify their installation and version:

```bash
docker --version && docker compose version
```

## 2. Install M3TAL via APT

Execute the following commands to install the M3TAL CLI binary and API daemon:

```bash
# 1. Add the GPG signing key
curl -fsSL https://jakej985-rgb.github.io/m3tal-core/KEY.gpg | sudo gpg --dearmor -o /usr/share/keyrings/m3tal-archive-keyring.gpg

# 2. Add the APT repository
echo "deb [signed-by=/usr/share/keyrings/m3tal-archive-keyring.gpg] https://jakej985-rgb.github.io/m3tal-core stable main" | sudo tee /etc/apt/sources.list.d/m3tal.list

# 3. Install
sudo apt update && sudo apt install -y m3tal
```

This installs the `m3tal` CLI binary (`/usr/bin/m3tal`) and the `m3tal-api.service` systemd daemon.

## 3. Run the Configuration Wizard

Initialize the core M3TAL configuration with the interactive wizard:

```bash
sudo m3tal config wizard
```

The wizard will prompt you for several configuration values. Explanation for key prompts:

*   **`DOMAIN`**: The primary domain name for services exposed via Traefik. Default is `localhost`. If you plan to expose services externally, provide your domain (e.g., `example.com`).
*   **`DASHBOARD_EXPOSE_MODE`**: Determines how the M3TAL Dashboard will be accessible.
    *   `local` (Default): The dashboard is directly exposed on a host port (default 8082). Access via `http://YOUR_IP:8082`. Best for local/LAN-only setups.
    *   `traefik`: The dashboard is routed through Traefik, accessible via `http://dash.YOUR_DOMAIN`. Requires Traefik to be running and a configured `DOMAIN`.
*   **`PUID` / `PGID`**: The User ID and Group ID that containers will run as. Typically `1000` for the default user. This ensures correct file permissions for mounted volumes.
*   **`TZ`**: Your system's timezone (e.g., `America/New_York`).
*   **`DASHBOARD_SECRET`**: A secret key used to secure dashboard sessions. A random string is generated by default.
*   **`ADMIN_PASSWORD`**: The initial password for the M3TAL Dashboard administrator account.
*   **Storage Paths (`BASE_STORAGE_PATH`, `CONFIG_PATH`, etc.)**: Base directories for M3TAL's persistent data and configuration files. Defaults usually point to `/mnt`.

Review and confirm the settings to save them to `/etc/m3tal/.env`.

## 4. Start the Routing Stack (Traefik)

The M3TAL routing stack manages network traffic and reverse proxying for your services.

```bash
m3tal up
```

This command initiates all Docker Compose files found in the `/docker/` directory. The `/docker/` path is a symlink to `/opt/m3tal/stack/`. The first stack to be started is the `routing` stack, which includes Traefik, the reverse proxy gateway that exposes services on port 80 (and 443 if SSL is configured).

## 5. Start the Dashboard

Deploy the M3TAL Dashboard container:

```bash
m3tal dash up
```

This command specifically manages the `m3tal-dashboard` container. It performs the following actions:
1.  Downloads the latest compose files (`m3tal-compose.yml`, `m3tal-compose.local.yml`, `m3tal-compose.traefik.yml`) from GitHub.
2.  Reads the `DASHBOARD_EXPOSE_MODE` from `/etc/m3tal/.env`.
3.  Starts the dashboard container using the appropriate compose override file based on your `DASHBOARD_EXPOSE_MODE` selection.

## 6. Open the Browser

Access the M3TAL Dashboard:

*   **If `DASHBOARD_EXPOSE_MODE` is `local`**: Open your browser to `http://YOUR_IP:8082` (replace `YOUR_IP` with the IP address of your host machine).
*   **If `DASHBOARD_EXPOSE_MODE` is `traefik`**: Open your browser to `http://dash.YOUR_DOMAIN` (replace `YOUR_DOMAIN` with the domain you configured in Step 3).

## 7. Log In

Use the following credentials to log in to the M3TAL Dashboard:

*   **Username**: `admin`
*   **Password**: The `ADMIN_PASSWORD` you set during the configuration wizard (Step 3).

**To change the dashboard password:**

```bash
sudo m3tal dashpass
```

Follow the prompts to set a new password for the `admin` user.

## Filesystem Contract

M3TAL utilizes specific paths for its operations and persistent data:

| Path                        | Purpose                                                      |
| :-------------------------- | :----------------------------------------------------------- |
| `/etc/m3tal/.env`           | Primary configuration file. Contains all environment variables for M3TAL components. Managed by `m3tal config wizard`. |
| `/var/lib/m3tal/state.db`   | SQLite database storing M3TAL's internal state. Auto-created by the API daemon. |
| `/opt/m3tal/stack/`         | Canonical directory for all Docker Compose files and Traefik dynamic configuration. |
| `/docker`                   | A symbolic link pointing to `/opt/m3tal/stack/`. This is the user-facing path for managing Docker Compose stacks. |
| `/docker/users.json`        | Stores M3TAL Dashboard user credentials. Managed by `m3tal dashpass`. |

## Port Table

Key ports used by the M3TAL ecosystem:

| Port | Service                               | Access                                    |
| :--- | :------------------------------------ | :---------------------------------------- |
| 80   | Traefik HTTP entry point              | Public (if Traefik is exposed)            |
| 8080 | M3TAL API daemon (Go)                 | Host-local (accessed by dashboard/Traefik) |
| 8081 | Traefik Dashboard (admin interface)   | Host-local only                           |
| 8082 | M3TAL Dashboard (Python/Flask)        | Direct port (local mode) or via Traefik (traefik mode) |

---

## Firewall Note

If you plan to expose Traefik and its routed services (including the M3TAL Dashboard in `traefik` mode) to the internet or your local network, you may need to adjust your firewall rules.

For UFW (Uncomplicated Firewall), allow HTTP traffic:

```bash
sudo ufw allow 80/tcp
```

## Service Management

The M3TAL API daemon runs as a systemd service. You can manage and monitor it using standard `systemctl` and `journalctl` commands:

*   **Check API service status**:
    ```bash
    systemctl status m3tal-api
    ```
*   **View API service logs in real-time**:
    ```bash
    journalctl -u m3tal-api -f
    ```
