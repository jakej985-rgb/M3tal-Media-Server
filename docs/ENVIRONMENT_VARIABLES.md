# Environment Variables Reference

All M3TAL system configurations are managed through environment variables, primarily stored in the `/etc/m3tal/.env` file. Both the `m3tal` CLI and all Docker Compose stacks read these variables from this file using the `--env-file` option, ensuring a consistent and centralized configuration across the entire M3TAL ecosystem.

## Detailed Environment Variable Reference

### Core Variables

These variables control the fundamental behavior and logging of the M3TAL API daemon and core services.

#### `HTTP_PORT`
- **Description**: The port on which the M3TAL API daemon (Go binary) listens for incoming requests. This port is typically only exposed on the host for internal use or via Traefik.
- **Default Value**: `8080`
- **Example Value**: `9090`
- **Component(s)**: `m3tal-api.service` (API daemon), Traefik (when routing to `api.DOMAIN`).

#### `STATE_DIR`
- **Description**: The directory where the M3TAL API daemon stores its SQLite database (`state.db`) and other runtime state. This path is also mounted into containers like the Dashboard for state access.
- **Default Value**: `./state`
- **Example Value**: `/var/lib/m3tal/state`
- **Component(s)**: `m3tal-api.service`, `m3tal-dashboard` container.

#### `LOG_LEVEL`
- **Description**: Controls the verbosity of logs generated by the M3TAL API daemon. Higher verbosity (e.g., `debug`) can be useful for troubleshooting.
- **Default Value**: `info`
- **Example Value**: `debug`, `warn`, `error`
- **Component(s)**: `m3tal-api.service` (API daemon).

#### `DEBUG_MODE`
- **Description**: When set to `true`, enables debug logging and potentially additional diagnostic features for the M3TAL API daemon, useful for development or advanced troubleshooting.
- **Default Value**: `false`
- **Example Value**: `true`
- **Component(s)**: `m3tal-api.service` (API daemon).

#### `METRICS_ENABLED`
- **Description**: Determines whether the M3TAL API daemon exposes Prometheus-compatible metrics endpoints for monitoring.
- **Default Value**: `true`
- **Example Value**: `false`
- **Component(s)**: `m3tal-api.service` (API daemon).

---

### Authentication Variables

These variables are crucial for securing access to the M3TAL dashboard and API.

#### `DASHBOARD_SECRET`
- **Description**: A long, random secret key used by the M3TAL Dashboard for session management, encryption, and securing internal communications.
  **Important**: This value is automatically generated on the first run of `m3tal init`. Users should **NOT** set this manually unless performing a credential rotation.
- **Default Value**: `change_me_immediately`
- **Example Value**: `a_very_long_random_string_of_characters`
- **Component(s)**: `m3tal-dashboard` container, `m3tal` CLI (during `init`).

#### `API_TOKEN`
- **Description**: An authentication token used to secure access to the M3TAL API daemon. This token is used by the CLI and Dashboard to communicate with the API.
  **Important**: This value is automatically generated on the first run of `m3tal init`. Users should **NOT** set this manually unless performing a credential rotation.
- **Default Value**: `change_me_api_token`
- **Example Value**: `another_long_random_string_for_api_auth`
- **Component(s)**: `m3tal-api.service`, `m3tal` CLI (during `init` and subsequent operations), `m3tal-dashboard` (for API communication).

#### `ADMIN_PASSWORD`
- **Description**: The initial password for the default 'admin' user in the M3TAL Dashboard. This can be changed securely after setup using the `m3tal dashpass` command.
- **Default Value**: `admin_pass`
- **Example Value**: `my_strong_admin_password`
- **Component(s)**: `m3tal-dashboard` container, `m3tal` CLI (`m3tal dashpass`).

---

### Network Variables

Configurations related to Docker networks and host IP addresses.

#### `NETWORK_NAME`
- **Description**: The base name for M3TAL's primary internal Docker network, used for inter-container communication. While the variable defaults to `m3tal`, the actual external Docker network used by the core control plane is typically named `proxy` in Docker Compose files.
- **Default Value**: `m3tal`
- **Example Value**: `m3tal_custom_network`
- **Component(s)**: All Docker Compose stacks (implicitly for network configuration).

#### `LOCAL_IP`
- **Description**: The IP address of the host machine. This is used by containers to correctly resolve `host.docker.internal` for communicating with host-bound services like the M3TAL API daemon.
- **Default Value**: `127.0.0.1`
- **Example Value**: `192.168.1.100`
- **Component(s)**: `m3tal-dashboard` (via `extra_hosts` for `host.docker.internal`), other service containers requiring host access.

---

### Storage Variables

Define the persistent storage locations for M3TAL's data.

#### `BASE_STORAGE_PATH`
- **Description**: The fundamental directory on the host filesystem where M3TAL stores all persistent data, including media, configuration files, and downloads.
  **Important**: While the default in the template is `./data`, in production M3TAL deployments, this variable typically defaults to `/mnt` to align with common Linux server storage conventions.
- **Default Value**: `./data`
- **Example Value**: `/mnt/m3tal_data`
- **Component(s)**: `m3tal-dashboard` container (volume mount), other service containers requiring persistent storage.

#### `MEDIA_PATH`
- **Description**: A subdirectory within `BASE_STORAGE_PATH` specifically designated for media files managed by M3TAL services.
- **Default Value**: `./data/media`
- **Example Value**: `/mnt/m3tal_data/media`
- **Component(s)**: `m3tal-dashboard` (implicitly via volume mounts), other service containers that handle media.

#### `CONFIG_PATH`
- **Description**: A subdirectory within `BASE_STORAGE_PATH` where M3TAL stores its internal configuration files, such as `users.json` for dashboard credentials.
- **Default Value**: `./data/config`
- **Example Value**: `/mnt/m3tal_data/config`
- **Component(s)**: `m3tal-dashboard` container (volume mounts), `m3tal` CLI.

#### `DOWNLOADS_PATH`
- **Description**: A subdirectory within `BASE_STORAGE_PATH` intended for downloaded files by various M3TAL services.
- **Default Value**: `./data/downloads`
- **Example Value**: `/mnt/m3tal_data/downloads`
- **Component(s)**: Other service containers that perform downloads (e.g., download clients).

---

### Traefik Variables

Control the behavior and routing of the Traefik reverse proxy.

#### `DOMAIN`
- **Description**: The base domain for your M3TAL deployment. Setting this variable is crucial for enabling Traefik's domain-based routing. When set, Traefik will automatically configure routes for `dash.DOMAIN` (M3TAL Dashboard) and `api.DOMAIN` (M3TAL API daemon).
- **Default Value**: `localhost`
- **Example Value**: `example.com`
- **Component(s)**: Traefik gateway (`routing-compose.yml`, dynamic config), `m3tal-dashboard` (via Traefik labels in `m3tal-compose.traefik.yml`).

#### `TRAEFIK_WEB_PORT`
- **Description**: The host port that Traefik uses for its primary HTTP entry point. This is typically port `80` for standard web traffic.
- **Default Value**: `80`
- **Example Value**: `8080` (if port 80 is in use by another service)
- **Component(s)**: `traefik` container.

#### `TRAEFIK_WEBHTTPS_PORT`
- **Description**: The host port that Traefik uses for its primary HTTPS entry point. This is typically port `443` for secure web traffic.
- **Default Value**: `443`
- **Example Value**: `8443`
- **Component(s)**: `traefik` container.

#### `TRAEFIK_DASHBOARD_PORT`
- **Description**: The internal port that Traefik uses for its own administration dashboard. On the host, this is typically mapped to `127.0.0.1:8081` for local access.
- **Default Value**: `8080`
- **Example Value**: `9000`
- **Component(s)**: `traefik` container.

---

### VPN Variables

These variables are used to configure VPN services within the M3TAL ecosystem.

#### `VPN_USER`
- **Description**: The username used for VPN client configurations, essential for authenticating with VPN service containers.
- **Default Value**: `user`
- **Example Value**: `m3tal_vpn_user`
- **Component(s)**: VPN service containers (if deployed).

#### `VPN_PASSWORD`
- **Description**: The password associated with the `VPN_USER`, used for authenticating VPN service containers.
- **Default Value**: `password`
- **Example Value**: `secure_vpn_pass123`
- **Component(s)**: VPN service containers (if deployed).

---

### System (Runtime) Variables

Control the runtime environment and exposure of Docker containers.

#### `DASHBOARD_PORT`
- **Description**: The port where the M3TAL Dashboard container listens internally (on `0.0.0.0`) and is subsequently exposed to the host (in `local` mode) or routed by Traefik (in `traefik` mode).
- **Default Value**: `8082`
- **Example Value**: `9000`
- **Component(s)**: `m3tal-dashboard` container, `m3tal` CLI (for local mode port mapping), Traefik (for Traefik mode).

#### `DASHBOARD_EXPOSE_MODE`
- **Description**: Controls how the M3TAL Dashboard is exposed to the network.
  - `local`: The dashboard port (`DASHBOARD_PORT`) is directly mapped to the host, accessible via `http://HOST_IP:DASHBOARD_PORT`. Best for LAN-only setups or first-time use.
  - `traefik`: The dashboard is exposed via the Traefik reverse proxy, accessible at `http://dash.DOMAIN`. Requires Traefik to be running.
- **Default Value**: `local`
- **Example Value**: `traefik`
- **Component(s)**: `m3tal` CLI (selects appropriate Docker Compose override), `m3tal-dashboard` (implicitly via chosen compose file).

#### `PUID`
- **Description**: The User ID (UID) that container processes should run as inside the container. This is primarily used to ensure consistent file permissions when volumes are mounted from the host filesystem.
- **Default Value**: `1000`
- **Example Value**: `1001`
- **Component(s)**: `m3tal-dashboard` container, `ollama` container, other service containers.

#### `PGID`
- **Description**: The Group ID (GID) that container processes should run as inside the container. Similar to `PUID`, this helps maintain correct file permissions on mounted volumes.
- **Default Value**: `1000`
- **Example Value**: `1001`
- **Component(s)**: `m3tal-dashboard` container, `ollama` container, other service containers.

#### `TZ`
- **Description**: Sets the timezone inside the container. This ensures that logs, timestamps, and time-based operations within the containers reflect the correct local time.
- **Default Value**: `America/Denver`
- **Example Value**: `Europe/London`, `Asia/Tokyo`
- **Component(s)**: `m3tal-dashboard` container, `ollama` container, other service containers.
