# Environment Variables Reference

As the M3TAL Ecosystem Documentation Architect, I've compiled this comprehensive reference for all environment variables used by the M3TAL system. These variables control the behavior of the M3TAL CLI, API daemon, Dashboard, and various Docker Compose stacks.

**All M3TAL environment variables are read from the `/etc/m3tal/.env` file.** Both the M3TAL CLI and all Docker Compose stacks utilize this file via the `--env-file` option, ensuring a centralized and consistent configuration across your entire M3TAL deployment. You can manage these variables easily using `m3tal config wizard` or `m3tal config set KEY value`.

## Detailed Environment Variable Reference

### Core Configuration

These variables control the fundamental operation and behavior of the M3TAL API daemon and core system components.

| Variable Name | Description                                                                                                                                                                                                                                                           | Default Value | Example Value          | Used By                                  |
| :------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------ | :--------------------- | :--------------------------------------- |
| `HTTP_PORT`   | The port on which the M3TAL API daemon listens for incoming HTTP requests. This is primarily for internal communication, with Traefik routing external requests to this port.                                                                                                | `8080`        | `8080`                 | `m3tal-api.service`                      |
| `STATE_DIR`   | Specifies the directory where the M3TAL API daemon stores its SQLite state database (`state.db`). This path is mounted into the dashboard container as `/docker/state`.                                                                                                 | `./state`     | `/var/lib/m3tal/state` | `m3tal-api.service`, `m3tal-dashboard` container |
| `LOG_LEVEL`   | Sets the logging verbosity for the M3TAL API daemon and other core components. Supported values include `debug`, `info`, `warn`, `error`. Higher verbosity (e.g., `debug`) is useful for troubleshooting.                                                                 | `info`        | `debug`                | `m3tal-api.service`, CLI                 |
| `PUID`        | The User ID (UID) under which container processes will run. This is crucial for ensuring proper file permissions for volumes mounted into containers, preventing permission denied errors. It should typically match the UID of the user running Docker on the host.      | `1000`        | `1001`                 | `m3tal-dashboard` container, user-defined stacks |
| `PGID`        | The Group ID (GID) under which container processes will run. Similar to `PUID`, this ensures correct group permissions for mounted volumes. It should typically match the GID of the user's primary group on the host.                                                       | `1000`        | `1001`                 | `m3tal-dashboard` container, user-defined stacks |
| `TZ`          | Sets the timezone for all M3TAL containers and the API daemon. This ensures consistent timestamps in logs and scheduled tasks. Use a standard TZ database name (e.g., `America/Los_Angeles`, `Europe/Berlin`).                                                             | `America/Denver` | `Europe/London`        | `m3tal-dashboard` container, user-defined stacks, `m3tal-api.service` |
| `DEBUG_MODE`  | A boolean flag to enable or disable debug logging and potentially other debug-specific features across M3TAL components. Set to `true` for detailed output during development or troubleshooting.                                                                              | `false`       | `true`                 | `m3tal-api.service`, `m3tal-dashboard` container, CLI |
| `METRICS_ENABLED` | A boolean flag to enable or disable the collection and exposure of application metrics (e.g., Prometheus-compatible endpoints). Set to `false` to reduce overhead if metrics are not being consumed.                                                                   | `true`        | `false`                | `m3tal-api.service`                      |

### Authentication & Security

These variables are critical for securing access to the M3TAL Dashboard and API.

| Variable Name     | Description                                                                                                                                                                                                                                                                                                                                                                   | Default Value            | Example Value       | Used By                                  |
| :---------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------- | :------------------ | :--------------------------------------- |
| `DASHBOARD_SECRET`| A strong, randomly generated secret key used by the M3TAL Dashboard for secure session management, cookie signing, and other cryptographic operations. **This value is automatically generated on first `m3tal init` and users should generally NOT set it manually unless performing a key rotation for security reasons.**                                            | `change_me_immediately`  | `super_secret_key_12345` | `m3tal-dashboard` container              |
| `API_TOKEN`       | A long-lived token used for authenticating requests made directly to the M3TAL API daemon, primarily by the CLI or external tools. This token grants administrative access to the API. **This value is automatically generated on first `m3tal init` and users should generally NOT set it manually unless performing a token rotation for security reasons.** | `change_me_api_token`    | `m3tal_api_token_xyz_abc` | `m3tal-api.service`, CLI                   |
| `ADMIN_PASSWORD`  | The default password for the initial "admin" user account created within the M3TAL Dashboard's `users.json` file. It is strongly recommended to change this password immediately after initial setup using `m3tal dashpass`.                                                                                                                                               | `admin_pass`             | `MySecureP@ssw0rd!` | `m3tal-dashboard` container (for `users.json` initialization) |

### Network Configuration

These variables define how M3TAL components communicate within the Docker network and with the host machine.

| Variable Name | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Default Value | Example Value     | Used By                                  |
| :------------ | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------ | :---------------- | :--------------------------------------- |
| `NETWORK_NAME`| The name of the Docker network used by M3TAL's core components for inter-container communication. While the primary control plane containers (like `m3tal-dashboard` and Traefik) often use an external `proxy` network for broader service integration, this variable can define default internal networks for other M3TAL stacks or user-defined services.                                                                                                                                                                                                                                                                                                          | `m3tal`       | `m3tal_network`   | M3TAL Docker Compose stacks (for internal network definition or reference) |
| `LOCAL_IP`    | The local IP address of the host machine. This can be used by services that need to explicitly bind to a specific IP or for internal communication within the host's network. In Docker Compose, services connect to the host machine via `host.docker.internal`, but `LOCAL_IP` can be used for specific needs.                                                                                                                                                                                                                                                                                                                                                                                                                                 | `127.0.0.1`   | `192.168.1.100`   | Potentially CLI and API for host interaction |

### Storage Paths

These variables define the filesystem locations where M3TAL stores its data, configurations, and user-generated content.

| Variable Name       | Description                                                                                                                                                                                                                                                                                                                                                                                                         | Default Value      | Example Value     | Used By                                  |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :----------------- | :---------------- | :--------------------------------------- |
| `BASE_STORAGE_PATH` | The root directory for all M3TAL data storage, including media, configurations, and downloads. **In production deployments, this variable often defaults to `/mnt` or a similar persistent storage mount point, diverging from the template's `./data` for local testing.** This directory is mounted into containers (e.g., `m3tal-dashboard`) typically as `/mnt`.                                                   | `./data`           | `/mnt/m3tal_data` | `m3tal-dashboard` container, user-defined stacks |
| `MEDIA_PATH`        | Specifies the subdirectory within `BASE_STORAGE_PATH` where media files (movies, TV shows, music, etc.) are expected to be stored. This path is then typically mounted into media server containers.                                                                                                                                                                                                                  | `./data/media`     | `/mnt/data/media` | User-defined media server stacks         |
| `CONFIG_PATH`       | Specifies the subdirectory within `BASE_STORAGE_PATH` (or an absolute path if defined) where M3TAL stores configuration files, including the state database. For the M3TAL Dashboard, the state database is accessed via `${CONFIG_PATH}/m3tal/state:/docker/state`. While the JSON default is `./data/config`, the `m3tal-compose.yml` often uses `/mnt/config` as a fallback for the `state.db` in production. | `./data/config`    | `/mnt/config`     | `m3tal-dashboard` container, `m3tal-api.service` |
| `DOWNLOADS_PATH`    | Specifies the subdirectory within `BASE_STORAGE_PATH` where downloaded files are stored. This path is typically mounted into download client containers (e.g., torrent clients, newsgroup downloaders).                                                                                                                                                                                                                 | `./data/downloads` | `/mnt/data/downloads` | User-defined download client stacks      |

### Traefik & Routing

These variables configure how M3TAL integrates with Traefik for reverse proxying and domain-based routing.

| Variable Name           | Description                                                                                                                                                                                                                                                                                                                                                                  | Default Value | Example Value | Used By                                  |
| :---------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------ | :------------ | :--------------------------------------- |
| `DOMAIN`                | The base domain name used for Traefik routing rules. Setting this enables specific routes like `dash.DOMAIN` for the M3TAL Dashboard and `api.DOMAIN` for the M3TAL API. If not set, services will only be accessible via IP and port or `localhost`.                                                                                                                            | `localhost`   | `example.com` | `routing-compose.yml` (Traefik), `m3tal-compose.traefik.yml` (Dashboard labels) |
| `DASHBOARD_PORT`        | The internal port on which the M3TAL Dashboard container listens. When `DASHBOARD_EXPOSE_MODE` is set to `local`, this port is directly exposed on the host machine.                                                                                                                                                                                                        | `8082`        | `8082`        | `m3tal-dashboard` container, `m3tal up` (local mode) |
| `DASHBOARD_EXPOSE_MODE` | Controls how the M3TAL Dashboard is made accessible. <br/> - `local`: The dashboard is exposed directly on the host's `DASHBOARD_PORT` (e.g., `http://HOST_IP:8082`). Ideal for LAN-only or initial setups. <br/> - `traefik`: The dashboard is routed via Traefik to `http://dash.DOMAIN`, requiring Traefik to be running. Best for domain-based and publicly exposed setups. | `local`       | `traefik`     | `m3tal dash up` command, `m3tal-compose.local.yml`, `m3tal-compose.traefik.yml` |
| `TRAEFIK_WEB_PORT`      | The port Traefik uses as its primary HTTP entry point for incoming web traffic. This is typically exposed on the host machine.                                                                                                                                                                                                                                                | `80`          | `80`          | `traefik` container (`routing-compose.yml`) |
| `TRAEFIK_WEBHTTPS_PORT` | The port Traefik uses as its primary HTTPS entry point for incoming secure web traffic. This is typically exposed on the host machine and requires proper TLS configuration.                                                                                                                                                                                                     | `443`         | `443`         | `traefik` container (`routing-compose.yml`) |
| `TRAEFIK_DASHBOARD_PORT`| The internal port on which Traefik's own dashboard is exposed within its container. While the default here is `8080`, M3TAL typically maps this to `127.0.0.1:8081:8080` on the host for local access via `http://localhost:8081`.                                                                                                                                         | `8080`        | `8081`        | `traefik` container (`routing-compose.yml`) |

### VPN Configuration

These variables are provided for integrating user-defined VPN client containers into your M3TAL ecosystem. They are not directly used by core M3TAL components but are commonly required by third-party application stacks.

| Variable Name | Description                                                                                    | Default Value | Example Value   | Used By                         |
| :------------ | :--------------------------------------------------------------------------------------------- | :------------ | :-------------- | :------------------------------ |
| `VPN_USER`    | The username for authenticating with a VPN service when running a VPN client container.        | `user`        | `m3taluser`     | User-defined VPN client containers |
| `VPN_PASSWORD`| The password for authenticating with a VPN service when running a VPN client container.        | `password`    | `SecureVPNPass123` | User-defined VPN client containers |
